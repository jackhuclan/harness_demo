# 第一部分 · PRD（产品需求文档）

## 1. 产品概述

### 1.1 项目背景

套刻量测设备（Overlay Metrology，OVL）在半导体制造中承担套刻误差量测职能，其全场景知识（Know-how）沉淀在工程师经验中，难以规模化复用。本产品将套刻量测设备全生命周期场景的 Know-how 沉淀为可编排的「技能」（Skill），依据用户自然语言意图主动调用，实现研发—量产全链路的智能化操作。

### 1.2 产品定位

套刻量测智能体（OVL Agent）：用户以自然语言提出需求，Agent 自动识别意图并调度对应技能，完成建处方、调处方、分析数据、监测与诊断设备等工作，并对各类参数、日志、数据进行记忆与分析。

### 1.3 价值定位

- **降门槛**：智能体协助建处方、调处方、分析数据、维护设备，降低设备使用门槛。
- **经验资产化**：设备操作过程、运行数据即时习得，跨班次复用，经验不随人走。
- **主动预警**：主动识别超标数据、预测部件更换，从"救火"变"预警"，减少批量不良流出。
- **人机协同**：关键决策交回人工，符合 Fab 安全责任边界，落地阻力小。

### 1.4 目标用户

- 设备工艺工程师、量测工程师、设备维护工程师等 Fab 一线操作与管理人员。

## 2. 系统架构

### 2.1 三层架构

```
① 用户意图层     自然语言输入 · 需求描述（无需传统菜单）
        ↓
② LLM 编排层     厂内 Edge / 本地部署 · 气隙 · 可降级离线规则引擎
   ├─ 意图识别
   ├─ 自动路由
   └─ 多技能串联
        ↓
③ 设备侧核心 Skill（可拓展）
   ├─ 软件编排：处方创建及优化 / 机台监测 / 机台诊断
   ├─ 分析决策：处方分析 / 量测数据分析 / 归因分析
   └─ 经验扩展：自定义 Skill
```

### 2.2 部署约束

- 半导体 Fab 全程气隙（Air-gap）环境。
- LLM 运行于厂内 Edge / 本地。
- 公有云仅用于研发 / 演示。
- 支持降级为离线规则引擎。

## 3. 核心功能需求

### 3.1 功能模块总览

| 功能编号前缀 | 模块 | 能力 | 优先级 | 说明 |
|------|------|------|------|------|
| FR-MGT | 处方管理 | 处方建立及调试、处方分析、处方优化 | 高 | 覆盖处方全生命周期 |
| FR-PDA | 生产数据分析 | 数据统计、异常分析、性能分解、归因分析、决策建议、补偿下发、多技能串联 | 高 | 7 项子能力 |
| FR-TMA | 机台监测分析 | 机台性能检测、性能趋势、硬件状态分析 | 中 | 机台自身状态评估与寿命预估 |
| FR-TDI | 机台诊断修复 | 报错根因识别、自动处置、用户介入验证 | 中 | 含经验反馈学习 |
| FR-CSK | 自定义 Skill | 自然语言 / 附件习得自定义技能 | 低 | 可自动按技能约定执行 |
| FR-SYS | 系统通用 | 意图识别路由、记忆沉淀、用户介入机制 | 高 | 全局能力 |

> **功能编号体系**：`FR-<模块前缀>-<序号>`（如 FR-PDA-001）。各功能验收标准编号为 `AC-<模块前缀>-<序号>-<项号>`，逐条见 §3.7。

### 3.2 处方管理

#### 3.2.1 处方建立及调试（FR-MGT-001）

- **入口**：自然语言指令（如「帮我给 Foup2 的 slot5 建个 OVL 处方」），或示例场景一键触发。
- **目标对象**：自动调度机台从指定 Foup / slot 加载硅片（如 Foup2 的 slot5），无需人工上下片（对应 FR-MGT-004）。
- **流程**：共 13 步，关键步骤需用户确认或介入（详见 §4.1）。
- **能力**：输入 WaferMap 参数、对准建模、创建 / 训练 Test、设置物理参数、选取量测 Field、设置 Data culling、设置 TIS Optimization、性能确认、自动分析量测性能、性能判断与收尾。

#### 3.2.2 处方分析（FR-MGT-002）

- **入口**：自然语言指令（如「分析下 ProductA_M1M2_Layer 这个处方」）。
- **能力**：
  - 展示处方基本信息概况（产品 / 层、标记类型、OVL Model、TIS 模式、所属机台、创建时间）。
  - 展示处方运行情况（近 30 天已量测 Lot / Wafer 数、测点成功率、硅片成功率）。
  - 测点失败原因归类统计（OVL 超限、TIS 超限、Qmerit 超限、聚焦失败、对准失败等）。
  - 基于运行数据生成优化建议（如 TIS 模式调整、开启 Auto Retrain Test）。

#### 3.2.3 处方性能优化（FR-MGT-003）

- **触发**：处方性能不满足规格（如重复性未达标）。
- **能力**：检索优化知识库，匹配同类历史优化记录，按历史成功率与预期改善自动排序推荐方案（如开启 Self-Calibration、自动跑 MRO、调整 ANRA 参数），支持一键应用或介入调整。

### 3.3 生产数据分析

| 功能编号 | 子能力 | 功能说明 |
|----------|--------|----------|
| FR-PDA-001 | 数据统计 | 统计生产片 OVL 情况（采样规模、X/Y 3σ、片内最大 3σ、TIS 3σ 等） |
| FR-PDA-002 | 异常分析 | 失败范围定位 + 数据报表 / 量测图像 / log 日志综合根因研判 |
| FR-PDA-003 | 性能分解 Budget | 分解 Raw / W1F1 / W3F3 / CPE / Residual，识别最大贡献项 |
| FR-PDA-004 | 归因分析 | PLS / field-to-field 分析，定位 overlay 偏大根因 |
| FR-PDA-005 | 决策建议 | 基于分析给出模型升级、采样、工艺等改进建议 |
| FR-PDA-006 | 补偿下发 R2R | 校正系数下发、阻尼更新、工艺复核通知、闭环回填 |
| FR-PDA-007 | 多技能串联 | 自动识别意图，串联多个技能定位根因并给出改进建议 |

**典型输入示例**：

- 「帮我看下这批 LOT 的统计结果」
- 「看下刚才跑的数据为什么大多都是 fail」
- 「上午这批 Lot 的数据差异有多大？主要贡献项是什么？」
- 「为什么这批 overlay 偏大，根因是什么？」
- 「针对这个问题该怎么改进、给个建议？」
- 「看一下上午跑的这批数据怎么样」

### 3.4 机台监测分析

| 功能编号 | 场景 | 能力 |
|----------|------|------|
| FR-TMA-001 | 机台性能检测 | 运行处方（如 Recipe: Tool Performance）统计机台本身性能：OVL 重复性 (3σ)、TIS Mean / 3σ、单点量测时间 (MAM) 等；识别超标并主动提议排查 |
| FR-TMA-002 | 机台性能趋势 | 回顾近 N 周机台性能趋势，对比 spec 判断是否逼近上限并给出建议 |
| FR-TMA-003 | 机台硬件状态分析 | 分析硬件（如量测光源）状态：拉取历史 PM 数据、拟合衰减趋势、预估剩余寿命与更换时点、建议提前排程 PM 备件 |

### 3.5 机台诊断修复

| 功能编号 | 场景 | 能力 |
|----------|------|------|
| FR-TDI-001 | 精对准失败 | 定位根因（图形匹配失败）→ 自动留存备用模板 → 支持用户介入重新运行验证（FR-TDI-002） |
| FR-TDI-001 | 粗聚焦失败 | 查看运行 log 识别根因（聚焦行程不足）→ 推荐修改参数（如 Focus Travel 50um→80um）→ 用户介入确认后复测（FR-TDI-002） |

**经验反馈学习（FR-TDI-003）**：用户自主排查到真正根因后（如相机 PEG 采图失败），可将该排查方向反馈给 Agent，Agent 习得并写入诊断记忆（diagnosis memory），后续同类报错优先按该方向排查。

### 3.6 自定义 Skill（FR-CSK）

- **入口**：用户通过纯自然语言，或「自然语言 + 附件」训练 Agent 习得自定义技能（FR-CSK-001）。
- **能力**：Agent 解析附件文档中的规则并存为技能，后续可按技能约定自动执行（FR-CSK-002）。
- **示例**：附件「动态采样规则.pdf」→ 习得技能「动态采样」，按来料滚动应用多种采样方案动态监测 Overlay，帮助分析不同采样方案的性能差异。

## 4. 关键交互流程

### 4.1 处方建立及调试流程（13 步）

| 步骤 | 环节 | 关键/介入 | 说明 |
|------|------|-----------|------|
| 1 | 输入 WaferMap 参数 | 否 | 晶圆尺寸、场尺寸、场 offset |
| 2 | 对准建模（Alignment Train） | 关键·可介入 | coarse → fine → LLC 三级通过，自动设置匹配阈值 |
| 3 | 创建 Test（设置 Target） | 关键·可介入 | 根据所选标记生成 Test 模板，设置 Target 位置 |
| 4 | 训练 Test | 关键·可介入 | 聚焦曲线及 kernel 信号质量良好，XY 内外层相关性达标 |
| 5 | 设置物理参数 | 关键·可介入 | SG/DG、Focus base、WLI、OVL Model |
| 6 | 自动选取量测 Field | 可介入 | 依据 Wafer Map 与采样规则自动选取 |
| 7 | 自动设置 Data culling | 可介入 | 异常点剔除阈值、边缘排除 |
| 8 | 自动设置 TIS Optimization | 可介入 | 校正工具引入的套刻偏移 |
| 9 | 处方创建完毕 | 否 | 组装完成，进入性能确认前待命 |
| 10 | 处方性能确认 | 关键 | 量测 + 重复性 / TIS / 残差分析 |
| 11 | 调用量测流程执行性能测试 | 可介入 | 可指定执行对象与范围，或自动跑片 |
| 12 | 自动分析量测性能 | 否 | 调用性能分析技能，输出重复性 / TIS / 模型残差 |
| 13 | 性能判断与收尾 | 关键（分支） | 满足规格 → 保存处方；不满足 → 进入处方优化 |

**性能分析核心指标（规格示例 < 0.6 nm）**：

| 指标 | 示例值 | 判定 |
|------|--------|------|
| 重复性 (3σ) | 0.42 nm | Pass |
| TIS | 0.18 nm | Pass |
| 模型残差 (RMS) | 0.31 nm | Pass |

### 4.2 处方优化流程

1. 用户触发「性能不满足，进入优化」（可指定目标 spec，如重复性需优于 0.25 nm）。
2. Agent 检索优化知识库，匹配同类历史优化记录。
3. 按历史成功率与预期改善自动排序推荐方案。
4. 用户选择「应用」或「介入调整」。
5. 执行优化链（设参 → 运行优化 → 性能测试确认），输出改善后指标。

**优化推荐示例（实测重复性 3σ = 0.41 nm，目标 0.25 nm）**：

| 优化动作 | 历史匹配 | 成功率 | 预期 3σ |
|----------|----------|--------|---------|
| ① 开启 Self-Calibration | 23 例 | 87% | 0.41 → 0.18 nm |
| ② 自动跑 MRO | 31 例 | 78% | 0.41 → 0.22 nm |
| ③ 调整 ANRA 参数 | 15 例 | 64% | 0.41 → 0.27 nm |

### 4.3 生产数据分析链路

```
数据统计 → 异常分析（规格判定） → 性能分解 Budget → 归因分析 → 决策建议 → 补偿下发 R2R
     → 复测回填（设备侧 OM 套刻量测执行）→ 验证闭环
```

**归因分析示例（边缘场 vs 其他场 · OVL 3σ 差异，nm）**：

| 区域 | X 3σ | Y 3σ | XY 综合 3σ |
|------|------|------|------------|
| 边缘场 | 6.2 | 5.8 | 8.5 |
| 其他场 | 3.8 | 3.5 | 5.2 |
| 差值（边缘−其他） | +2.4 | +2.3 | +3.3 |

> 结论：field-to-field 残差集中于边缘场 → 边缘 overlay 恶化严重，可能为 etch / CMP 引入的工艺误差。

**性能分解 Budget 示例**：最大贡献项 Raw · Common（σ² ≈ 8.0），W1F1 仍主导，建议优先收敛机台级偏差。

### 4.4 异常诊断链路

1. 定位失败范围（判断是否整批 fail，或为单片 / 局部失败）。
2. 失败统计（片内失败测点分布、识别失败 / 超限分类）。
3. 查看量测图像（标记识别失败：边缘模糊、对比度下降、ROI 信噪比不足）。
4. 核对 OVL 报表（超限测点分布）。
5. 综合研判（图像 + 数据 + log 日志）确定根因。
6. 生成处置建议。

**示例：Wafer 9 失败根因研判**：

- Wafer 9 共 17 场 × 4 = 68 个测点，52 个 fail（76%）：标记识别失败 38 点、OVL 超限 14 点。
- 52 个失败测点中 47 个（90%）对应图像中标记脏污 / 破损区域。
- 同 LOT 其余 24 片 fail 率 < 1%，设备 log 无光学 / 机械异常。
- **根因**：Wafer 9 来料标记脏污破损（非机台或工艺系统性问题）。
- **处置**：清洁 / re-mark 后重测该片，或标记该片异常并剔除；复测由 OM 套刻量测执行（设备侧）。

### 4.5 机台监测分析链路

1. 自动加载晶圆（Foup / slot）。
2. 识别并运行处方（如 Recipe: Tool Performance）。
3. 展示性能测试结果（重复性 / TIS / MAM 等，判定是否在控）。
4. 持续监测，识别超标后主动提议排查（按历史命中率自动排序可能原因）。
5. 用户确认后逐项排查，定位根因（如 SFO 漂移）。
6. 执行修复（如更新 SFO）→ 重新执行性能测试验证。

**机台性能检测结果示例（Tool Performance，首次）**：

| 指标 | 数值 | 判定 |
|------|------|------|
| OVL 重复性 (3σ) | 0.21 nm | 在控（spec 0.25 nm） |
| TIS Mean | 0.17 nm | 在控 |
| TIS 3σ | 0.24 nm | 在控 |
| 单点量测时间 (MAM) | 0.28 s | 在控 |

**重复性超标（0.87 nm）可能原因排序示例**：

| 可能原因 | 历史匹配 | 成功率 | 预期改善 (3σ) | 优先级 |
|----------|----------|--------|---------------|--------|
| ① Stage 稳定性 | 23 例 | 71% | 0.87 → 0.52 nm | 中 |
| ② SFO 漂移 | 38 例 | 86% | 0.87 → 0.21 nm | 高 |
| ③ 光源稳定性超标 | 19 例 | 58% | 0.87 → 0.61 nm | 中 |
| ④ 光阑零位漂移 | 12 例 | 47% | 0.87 → 0.66 nm | 低 |

**硬件状态分析示例（量测光源）**：

- 历史 9 期 PM 数据，亮度月均衰减约 1.9%（R²≈0.99）。
- 当前亮度 85%（第 9 月），接近建议更换阈值 80%。
- 按当前衰减速率，预计约第 11 个月跌至阈值以下、需更换光源（距今约 2 个月）。
- 建议提前排程 PM 备件。

### 5.1 部署与安全

- 关键决策交回人工，符合 Fab 安全责任边界。

### 5.4 经验沉淀与反馈学习

- 设备操作过程、运行数据即时习得，跨班次复用。
- 用户反馈的排查方向 / 经验可即时习得并写入记忆（如 diagnosis memory），反哺后续任务。
- 处方优化、机台诊断均基于历史记录的成功率与预期改善排序推荐。

### 5.5 智能路由

- 基于自然语言路由规则识别意图并匹配对应能力。
- 未精准匹配时给出引导提示（可描述统计、异常、分解、归因、决策或补偿需求）。

## 3. 功能需求规格

> 以下按模块逐条给出功能需求详细规格。统一字段含义：**优先级、描述、输入、处理、输出、前置条件、后置条件、异常处理、验收标准**。

### 3.1 系统通用（FR-SYS）

#### FR-SYS-001 自然语言意图识别与路由
- **优先级**：高
- **描述**：接收用户自然语言指令，识别意图并路由至对应技能；未匹配时给出引导。
- **输入**：自然语言指令文本。
- **处理**：基于意图路由规则匹配（如统计 / 异常 / 分解 / 归因 / 决策 / 补偿等关键词）；无法匹配时触发引导提示。
- **输出**：路由结果（目标技能）、识别到的目标对象（如 Foup/slot）、或引导提示。
- **前置条件**：用户输入非空。
- **后置条件**：进入对应技能执行流程，或展示引导。
- **异常处理**：输入为空则提示；多意图歧义时按优先级默认或请用户澄清。
- **验收标准**：AC-SYS-001-01。

#### FR-SYS-002 记忆与经验沉淀
- **优先级**：高
- **描述**：记忆设备操作过程、运行数据、用户反馈经验，跨会话复用。
- **输入**：操作事件、量测数据、用户反馈文本。
- **处理**：结构化写入记忆（含诊断记忆）；后续任务检索复用。
- **输出**：可检索的记忆记录、可复用的经验。
- **前置条件**：数据来源可用。
- **后置条件**：记忆持久化，可在后续会话引用。
- **异常处理**：写入失败需记录且不阻断当前任务。
- **验收标准**：AC-SYS-002-01。

#### FR-SYS-003 用户介入机制
- **优先级**：高
- **描述**：关键步骤自动暂停，等待用户确认或介入，介入后状态可回退可继续。
- **输入**：用户确认 / 介入指令、参数修改。
- **处理**：标记为「关键」的步骤在触发点暂停，展示介入说明与「介入调整」入口；用户确认后继续，介入后应用修改。
- **输出**：确认按钮、介入调整面板、步骤状态。
- **前置条件**：当前步骤被标记为「关键」或「可介入」。
- **后置条件**：流程按用户选择继续或调整后继续。
- **异常处理**：介入修改非法时提示并保持暂停。
- **验收标准**：AC-SYS-003-01。

### 3.2 处方管理（FR-MGT）

#### FR-MGT-004 机台调度与硅片加载
- **优先级**：高
- **描述**：依据指令中的 Foup/slot 目标，自动调度机台加载硅片。
- **输入**：Foup 标识、slot 序号（如 Foup2 · slot5）。
- **处理**：读取硅片 ID 与规格 → 下发 LOAD 指令 → 机械手拾取 → 传送至量测卡盘 → 真空吸附/对心。
- **输出**：加载状态序列、加载完成确认（Wafer ID、晶圆规格）。
- **前置条件**：机台在线、目标 Foup/slot 存在。
- **后置条件**：硅片就绪，进入建方流程。
- **异常处理**：拾取/传送失败给出明确状态提示并停止。
- **验收标准**：AC-MGT-004-01、AC-MGT-004-02。

#### FR-MGT-001 处方建立及调试
- **优先级**：高
- **描述**：引导完成 13 步建方流程，关键步骤由用户确认或介入。
- **输入**：建方指令、WaferMap 参数（晶圆尺寸、场尺寸、场 offset）、各步骤确认/参数。
- **处理**：按 13 步顺序执行（步骤表见第一部分 §4.1）。
- **输出**：逐步执行卡片、性能分析结果、保存确认。
- **前置条件**：硅片已加载（FR-MGT-004）、WaferMap 参数已提供。
- **后置条件**：处方保存并可被生产测量调用。
- **异常处理**：任一关键步骤未确认则暂停；性能不满足走优化分支。
- **验收标准**：AC-MGT-001-01、AC-MGT-001-02、AC-MGT-001-03。

**性能分析核心指标（规格示例 < 0.6 nm）**：重复性 (3σ) 0.42 nm / TIS 0.18 nm / 模型残差 (RMS) 0.31 nm，均 Pass。

#### FR-MGT-002 处方分析
- **优先级**：高
- **描述**：分析指定处方的运行情况并生成优化建议。
- **输入**：处方名（如 ProductA_M1M2_Layer）。
- **处理**：展示基本信息 → 展示近 30 天运行统计 → 测点失败归类 → 生成优化建议。
- **输出**：四部分分析卡片。
- **前置条件**：处方存在且有运行记录。
- **后置条件**：给出可执行的优化建议。
- **异常处理**：无运行数据时提示并仅展示基本信息。
- **验收标准**：AC-MGT-002-01、AC-MGT-002-02。

**示例（近 30 天）**：已量测 42 Lot / 980 Wafer；测点成功率 99.9%（失败 100 / 总 98,000）；硅片成功率 99.8%。失败归类：OVL 超限 38、TIS 超限 20、Qmerit 超限 18、聚焦失败 14、对准失败 10。

#### FR-MGT-003 处方性能优化
- **优先级**：高
- **描述**：处方性能不满足规格时，检索知识库并推荐带成功率/预期改善的优化方案。
- **输入**：不达标指标与目标 spec（如重复性需优于 0.25 nm）。
- **处理**：检索知识库 → 按成功率/预期改善排序推荐 → 用户应用或介入 → 执行优化链（设参 → 运行优化 → 性能测试确认）。
- **输出**：优化方案推荐表、优化执行链、改善后指标。
- **前置条件**：处方性能判定为不满足。
- **后置条件**：指标改善达标后保存处方。
- **异常处理**：无匹配历史时提示并给出通用建议。
- **验收标准**：AC-MGT-003-01、AC-MGT-003-02。

**推荐方案示例（实测 3σ=0.41 nm，目标 0.25 nm）**：Self-Calibration（87%，0.41→0.18）/ MRO（78%，0.41→0.22）/ ANRA（64%，0.41→0.27）。

### 3.3 生产数据分析（FR-PDA）

#### FR-PDA-001 数据统计
- **优先级**：高
- **描述**：统计生产片 OVL 情况。
- **输入**：LOT 范围。
- **处理**：统计采样规模、X/Y 全片均值 3σ、片内最大 3σ、TIS 3σ；对超规格项告警。
- **输出**：数据统计卡片（含告警标注）。
- **前置条件**：对应量测数据已采集。
- **后置条件**：数据可被后续分解/归因使用。
- **验收标准**：AC-PDA-001-01、AC-PDA-001-02。

**示例（LOT-2207）**：25 片 × 17 场 × 4 点；X 3σ 均值 4.1 / Y 3σ 3.8 / 最大片内 X 3σ ⚠ Wafer 9 = 6.2 nm / TIS 3σ 0.9 nm。

#### FR-PDA-002 异常分析（失败根因研判）
- **优先级**：高
- **描述**：定位失败范围并综合数据报表/量测图像/设备 log 研判根因。
- **输入**：异常或失败相关指令。
- **处理**：定位失败范围 → 失败统计 → 查看量测图像 → 核对 OVL 报表 → 综合研判 → 生成处置建议。
- **输出**：失败范围、失败统计、根因研判结论、处置建议。
- **前置条件**：存在失败量测数据。
- **后置条件**：给出可执行处置建议。
- **异常处理**：数据/图像/log 缺失时标注证据不足。
- **验收标准**：AC-PDA-002-01、AC-PDA-002-02。

**示例（Wafer 9）**：68 测点 52 fail（76%），其中 47（90%）对应图像标记脏污/破损；同 LOT 其余 24 片 fail <1%，log 无异常 → 根因：来料标记脏污破损。

#### FR-PDA-003 性能分解 Budget
- **优先级**：中
- **描述**：分解套刻误差来源，识别最大贡献项。
- **输入**：量测数据集。
- **处理**：分解 Raw / W1F1 / W3F3 / CPE / Residual，统计各分量。
- **输出**：分解图、各分量值、最大贡献项结论。
- **前置条件**：具备可分解的量测数据。
- **后置条件**：为归因与决策提供依据。
- **验收标准**：AC-PDA-003-01。

**示例**：最大贡献项 Raw · Common（σ²≈8.0），W1F1 仍主导。

#### FR-PDA-004 归因分析
- **优先级**：中
- **描述**：基于 PLS / field-to-field 定位 overlay 偏大根因。
- **输入**：量测数据、场分布。
- **处理**：PLS 建模、field-to-field 残差分析，识别边缘场/工艺/机台因素。
- **输出**：残差分布、区域对比、相关性证据（R²）、疑似因素。
- **前置条件**：具备量测与场分布数据。
- **后置条件**：支撑决策建议。
- **验收标准**：AC-PDA-004-01。

**示例（边缘场 vs 其他场，XY 综合 3σ）**：边缘 8.5 / 其他 5.2 / 差值 +3.3 nm。

#### FR-PDA-005 决策建议
- **优先级**：中
- **描述**：基于分析结果生成可执行改进建议。
- **输入**：归因/分解结果。
- **处理**：生成模型升级、采样、工艺等建议。
- **输出**：决策建议列表。
- **前置条件**：有分析结论支撑。
- **后置条件**：可进入补偿下发。
- **验收标准**：AC-PDA-005-01。

**示例**：线性→iHOPC（3 阶 15 参，降 residual ~15–20%）；边缘场加严采样；etch 功率窗口复核。

#### FR-PDA-006 补偿下发 R2R
- **优先级**：中
- **描述**：下发校正系数并进入批次间补偿闭环。
- **输入**：校正决策。
- **处理**：下发校正系数 → 更新 R2R 阻尼 → 通知工艺复核 → 等待设备侧复测回填。
- **输出**：下发状态、闭环状态。
- **前置条件**：校正方案已确认。
- **后置条件**：进入复测回填闭环（设备侧）。
- **异常处理**：下发失败需提示并支持重试。
- **验收标准**：AC-PDA-006-01。

#### FR-PDA-007 多技能串联
- **优先级**：高
- **描述**：单条指令自动串联多个技能定位根因并给建议。
- **输入**：自然语言指令（如「看一下上午跑的这批数据怎么样」）。
- **处理**：自动识别意图，依序调用统计→异常→分解→归因→决策→补偿。
- **输出**：完整链路结论（含可能原因与改进建议）。
- **前置条件**：量测数据可用。
- **后置条件**：形成闭环结论。
- **验收标准**：AC-PDA-007-01。

### 3.4 机台监测分析（FR-TMA）

#### FR-TMA-001 机台性能检测
- **优先级**：中
- **描述**：运行指定处方统计机台本身性能并识别超标。
- **输入**：机台性能指令（如 Foup1 · slot2 + Recipe: Tool Performance）。
- **处理**：自动加载晶圆 → 识别并运行处方 → 统计重复性/TIS/MAM → 判定在控；超标时按历史命中率排序候选原因。
- **输出**：性能检测结果、超标原因排序。
- **前置条件**：机台在线、处方存在。
- **后置条件**：性能配置可记忆；超标进入排查。
- **验收标准**：AC-TMA-001-01、AC-TMA-001-02。

**示例（首次全在控）**：重复性 0.21（spec 0.25）/ TIS Mean 0.17 / TIS 3σ 0.24 / MAM 0.28 s。超标（0.87）排序：SFO（86%）> Stage（71%）> 光源（58%）> 光阑（47%）。

#### FR-TMA-002 机台性能趋势
- **优先级**：中
- **描述**：回顾近 N 周机台性能趋势，对比 spec 判定逼近程度。
- **输入**：趋势查询指令（如「近两个月机台性能」）。
- **处理**：拉取历史监测数据 → 绘制趋势 → 对比 spec。
- **输出**：趋势图、逼近判定、建议。
- **前置条件**：有历史监测记录。
- **后置条件**：给出 PM/复核建议。
- **验收标准**：AC-TMA-002-01。

**示例**：重复性末周 0.24 nm，逼近 spec（0.25），仍可控但上行，建议自查 TIS/calibration 并安排 PM。

#### FR-TMA-003 机台硬件状态分析
- **优先级**：中
- **描述**：分析硬件状态并预估剩余寿命与更换时点。
- **输入**：硬件状态查询（如「量测光源状态」）。
- **处理**：拉取历史 PM 数据 → 拟合衰减趋势（R²）→ 外推至更换阈值。
- **输出**：衰减曲线、R²、剩余寿命、更换时点、PM 建议。
- **前置条件**：有历史 PM 数据。
- **后置条件**：生成备件排程建议。
- **验收标准**：AC-TMA-003-01。

**示例**：光源月均衰减 ~1.9%（R²≈0.99），当前 85%（第 9 月），阈值 80%，预计第 11 月更换（距今约 2 个月）。

### 3.5 机台诊断修复（FR-TDI）

#### FR-TDI-001 报错诊断与根因定位
- **优先级**：高
- **描述**：识别报错类型并调取上下文定位根因。
- **输入**：报错/诊断指令。
- **处理**：识别报错类型（精对准/粗聚焦等）→ 调取运行 log 与上下文 → 定位根因 → 排除非目标原因。
- **输出**：报错信息、根因结论。
- **前置条件**：机台处于报错状态或用户发起诊断。
- **后置条件**：进入处置流程。
- **验收标准**：AC-TDI-001-01。

#### FR-TDI-002 自动处置与用户介入验证
- **优先级**：高
- **描述**：生成处置建议，关键处置前暂停等待确认，复测验证。
- **输入**：处置确认、验证指令。
- **处理**：生成处置建议 → 关键处置暂停等确认 → 执行处置 → 重新量测/复测验证。
- **输出**：处置建议、执行状态、复测结果。
- **前置条件**：已定位根因。
- **后置条件**：指标恢复、机台恢复正常运行。
- **验收标准**：AC-TDI-002-01。

**示例**：粗聚焦失败 → 根因聚焦行程不足 → 建议 50um→80um → 确认后复测通过。

#### FR-TDI-003 经验反馈学习
- **优先级**：中
- **描述**：习得用户反馈的真实根因，后续优先排查。
- **输入**：用户反馈的根因方向（如相机 PEG 采图失败）。
- **处理**：解析并写入诊断记忆，标注来源为用户经验。
- **输出**：记忆确认、习得内容说明。
- **前置条件**：用户提供真实根因反馈。
- **后置条件**：后续同类报错优先按该方向排查。
- **验收标准**：AC-TDI-003-01。

### 3.6 自定义 Skill（FR-CSK）

#### FR-CSK-001 自定义技能习得
- **优先级**：低
- **描述**：解析自然语言/附件规则并生成技能。
- **输入**：自然语言指令、可选附件（如动态采样规则.pdf）。
- **处理**：解析规则 → 结构化技能约定 → 向用户确认。
- **输出**：技能对象、规则说明。
- **前置条件**：提供规则来源。
- **后置条件**：技能入库可用。
- **验收标准**：AC-CSK-001-01。

#### FR-CSK-002 自定义技能执行
- **优先级**：低
- **描述**：后续任务自动按已习得技能约定执行。
- **输入**：匹配的任务/处方请求。
- **处理**：匹配技能 → 按约定规则执行。
- **输出**：按技能约定执行的产线动作与结果。
- **前置条件**：技能已习得且任务匹配。
- **后置条件**：规则应用正确，性能可对比分析。
- **验收标准**：AC-CSK-002-01。
